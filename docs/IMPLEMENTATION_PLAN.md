# 需求理解与完整实施方案

## 1. 项目定位

这不是一个以视觉炫技为目标的作品集，而是一份可持续维护的个人技术档案。它同时服务三类任务：

1. 招聘人员在三分钟内理解专业背景、核心能力、项目经验和联系方式；
2. 技术人员通过文章、项目决策和验证过程判断工程深度；
3. 作者长期沉淀内容、工具、项目复盘和成长记录。

内容表达遵循真实、克制、可验证。项目不宣称“精通全部技术”，技术栈必须说明实际使用场景和熟悉程度。

## 2. 用户需求分析

| 用户 | 核心问题 | 设计响应 |
|---|---|---|
| 招聘人员 | 你是谁、做过什么、是否匹配 | 首页能力摘要、精选项目、关于页、联系方式 |
| 技术负责人 | 是否有系统思考与交付能力 | 项目背景、职责、架构、难点、验证和结果 |
| 同行工程师 | 内容是否能解决真实问题 | 分类文章、目录、代码、图表、相关文章 |
| 导师与合作方 | 背景、方向与成长潜力 | 时间线、研究方向、技术理念、持续计划 |
| 作者本人 | 是否易写、易维护、可扩展 | Markdown、结构化元数据、管理 API、稳定 URL |

## 3. 功能需求

- 首页：首页定位、当前方向、技术栈、精选项目、最新文章、当前计划和联系入口。
- 内容：文章列表、分类、标签、详情、目录、阅读时间、相关文章、RSS、永久链接。
- 项目：背景、问题、职责、技术栈、架构、难点、方案、成果、状态和相关文章。
- 档案：关于、技术栈、时间线、简历联系入口。
- 检索：标题、摘要、正文、分类、标签和项目统一搜索。
- 管理：登录、文章/项目/分类/标签/时间线/媒体/设置/链接管理、自动保存、备份、日志和统计。
- 平台：SEO、404、深浅色、响应式、无障碍、访问统计和可选评论。

## 4. 非功能需求

- 性能：常规网络首屏目标小于 2 秒；Lighthouse Performance ≥ 90、Accessibility ≥ 90、SEO ≥ 95、Best Practices ≥ 90。
- 安全：Argon2id 密码、HttpOnly Cookie、CSRF、速率限制、严格 CORS、上传白名单、参数化查询、日志脱敏和定期备份。
- 可维护：前后端类型明确、模块边界稳定、配置与代码分离、迁移可追踪、错误结构统一。
- SEO：服务端生成公开页面、语义化 HTML、独立元数据、Canonical、Sitemap、RSS、结构化数据与稳定 slug。
- 保密：发布前执行十项内容审查，所有工作案例使用脱敏、模拟或重新绘制资料。

## 6. UI 设计规范

- 风格：苹果式留白、清晰层级、克制动效、内容优先。
- 色彩：浅色背景 `#F7F7F5`，深色背景 `#151817`，强调蓝 `#1469D8`。
- 字体：系统中文无衬线字体栈；代码使用 `SFMono-Regular / Menlo / Consolas`。
- 圆角：按钮 12px、内容卡片 22px、重点容器 28px。
- 间距：以 4px 为基础网格；页面主节奏 24 / 48 / 72 / 112px。
- 动效：200–250ms，仅用于反馈、导航和卡片层级；尊重 `prefers-reduced-motion`。
- 可访问性：键盘可达、可见焦点、语义标签、颜色对比和清晰替代文本。

## 7. 系统模块

- 前台壳层：导航、主题、页脚和响应式。
- 内容模块：文章、分类、标签、Markdown、代码、图表、公式与 SEO。
- 项目模块：项目档案、技术栈、架构与关联文章。
- 档案模块：关于、技术栈、时间线。
- 搜索模块：PostgreSQL `ILIKE`/`pg_trgm` 搜索服务，覆盖文章、项目、分类和标签。
- 管理模块：认证、编辑、媒体、设置、日志、统计和备份。
- 基础设施：结构化日志、统一异常、持久卷、备份和部署。

## 9. 核心实体

`users`、`posts`、`categories`、`tags`、`post_tags`、`projects`、`project_tags`、`timelines`、`media_files`、`site_settings`、`links`、`operation_logs`，以及可选的 `comments`、`page_views`。

所有业务表使用 UUID 主键、UTC 创建/更新时间；内容表采用 `deleted_at` 软删除；关联表使用复合唯一约束。

## 10. 开发阶段与顺序

1. 需求与设计：定位、信息架构、设计系统、数据、API 和架构。
2. 基础框架：前台、后端、数据库、响应、异常、日志。
3. 前台功能：首页、文章、项目、档案、搜索、主题和响应式。
4. 管理后台：认证、编辑器、分类标签、媒体、设置、备份。
5. 优化：SEO、性能、安全、测试、错误页和移动端。
6. 部署：Linux、PostgreSQL、Nginx、Let's Encrypt、日志和备份。

## 11. 重点技术风险

- React SPA 的 SEO 风险：公开内容必须服务端生成或预渲染，不能只依赖客户端请求。
- Markdown XSS：原始 HTML 默认禁用；渲染结果必须白名单清洗。
- 管理认证：不把长期 JWT 放入 localStorage；使用短会话 HttpOnly Cookie 和 CSRF Token。
- 全文搜索：中文分词需要 `pg_jieba`、PGroonga 或独立搜索服务评估；MVP 使用标题、摘要和标签索引。
- 上传安全：检查扩展名、MIME、文件头、尺寸和大小；随机化对象名；公开和私有桶分离。
- 内容泄密：技术正确不代表可以公开；发布流程必须包含保密审查。
- 历史部署元数据：保留既有 Sites 项目标识，但正式域名只运行自有 Linux 上的完整 FastAPI/PostgreSQL 系统。
- 过度建设：评论、Redis、队列和复杂搜索在流量与场景出现后引入。
