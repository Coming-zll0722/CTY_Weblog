## 运营节奏

- 每两周：一篇可独立解决问题的工程文章；
- 每月：一次项目进展或学习路线更新；
- 每季度：整理一个完整项目案例并复核旧文章；
- 每年：年度复盘、技术方向调整和陈旧内容归档。

## 内容库初始化

仓库在 `backend/app/content_library.py` 维护一套可审查的初始内容包。它通过现有
SQLAlchemy 模型写入 PostgreSQL，不是第二套前端内容源。

```powershell
cd backend
.\.venv\Scripts\cty-log.exe seed-content
```

导入命令以 slug 判断文章、项目、分类和标签是否已经存在，以日期和标题判断时间线，
可重复执行。它只创建缺少的内容，不覆盖后台中已经存在的文章或项目。唯一例外是旧版
`protocol-test-platform` 示例：仅当其所有已知字段仍与旧种子内容完全一致时，才升级为
完整项目档案；任何人工编辑都会使升级自动跳过。

初始内容中，完全依据公开仓库或通用模拟材料完成保密检查的文章可公开；其余文章保持
草稿。新增项目明确区分真实公开仓库、模拟原型和持续学习记录。

## 质量标准

每篇文章至少包含明确问题、边界、方案依据和验证结果。代码必须可解释；数字必须有来源；工作经验必须脱敏。标题不使用夸张承诺，摘要说明读者能获得什么。

## 后续迭代

当前已完成 Markdown 管理、实时预览、草稿自动保存、Prism 常用语言代码高亮与复制、KaTeX、Mermaid、图片灯箱、版本冲突、slug 重定向、发布审查、项目—文章关联和匿名访问统计。

后续按真实使用量推进：

1. 内容规模扩大后评估 PGroonga、`pg_jieba` 或独立搜索服务；
2. 只有持久卷容量或异地容灾出现实际需求时，才为 `MediaStorage` 实现对象存储并增加派生尺寸与 `srcset`；
3. 多 API 实例前将登录限流迁移到共享数据库或专用限流存储；
4. 有明确审核和反垃圾能力后再启用评论；
5. 框架支持稳定 nonce 后收紧 CSP 并移除 `'unsafe-inline'`。
