# 工程审计与实施基线（2026-07-24）

## 1. 当前工程审计结果

- Git：`main` 跟踪 `sites-origin/main`，工作区在审计开始时无未提交修改。远端为既有 Sites 源仓库，本轮不推送。
- Sites：`.openai/hosting.json` 已绑定现有项目，项目当前为仅指定账户可访问；保留项目 ID、访问策略和既有部署，不创建新项目、不发布新版本。
- 前端：React 19 + TypeScript 5.9 + Vinext/Vite，公开页面可构建并服务端渲染。
- 后端：FastAPI、SQLAlchemy 2、Pydantic 2、Alembic 和 PostgreSQL 的目录与依赖已建立，但业务实现仍是骨架。
- 数据库：存在初始迁移和主要模型，但模型、迁移、Schema 与 API 尚未完全同步。
- 部署：已有单一 Docker Compose、前后端 Dockerfile 和 Nginx 示例；未区分开发/生产，也缺少迁移、备份、非 root、日志轮转和回滚闭环。

## 2. 已实现功能

- 首页、文章列表/详情、项目列表/详情、技术栈、时间线、关于、搜索、404、RSS、Sitemap、robots。
- 响应式页面、深浅色主题、基础 SEO 元数据、RSS 和站点地图。
- FastAPI 健康检查、统一成功响应外形、请求 ID 和基础结构化日志。
- 文章、项目、分类、标签、时间线、媒体、设置、链接、日志、评论和访问统计的初始数据模型。
- 前端生产构建和 3 个服务端渲染测试通过。

## 3. 占位与缺失功能

- `data/site.ts` 仍是前台文章、项目和搜索的生产数据源。
- 文章正文和项目详情为固定模板，没有渲染数据库中的 Markdown。
- 登录及文章写接口返回 501；项目、时间线、搜索、统计和备份接口为演示空数据。
- 没有真实会话 Cookie、CSRF、角色验证、登录失败限制、修改密码或退出登录。
- 没有 service/repository 边界、真实 CRUD、软删除恢复、乐观锁、slug 重定向或发布保密检查。
- 管理后台仅为静态展示，不具备编辑、预览、自动保存、媒体、设置、日志、统计和备份能力。
- Markdown 尚未实现安全清洗、代码高亮、KaTeX、Mermaid、图片放大、目录和阅读进度的真实内容流。
- 缺少分类页、标签页、500 页面和联系页独立实现。
- 缺少受控本地上传、对象存储接口、图片头校验和派生图片。
- 自动化测试覆盖不足，尚未覆盖目标列出的认证、CRUD、冲突、搜索、上传、分页和集成场景。

## 4. 现有架构问题

- 路由层直接持有演示数据，模型存在但数据库会话未进入业务流程。
- 前端与后端各有一套内容数据，容易产生字段、排序和发布状态不一致。
- `TimestampMixin` 被用于不需要软删除的实体，且部分纯表缺少数据库默认 UUID。
- 模型缺少 `version`、项目结构化字段、项目文章关联、重定向和备份记录。
- 统一异常处理只覆盖未处理异常，HTTP 与校验错误仍返回 FastAPI 默认结构。
- 上传只检查声明 MIME 和大小，未检查扩展名、文件头、路径与持久化。
- ESLint 扫描 `work/package-stage` 生成物，导致检查出现大量无关问题。

## 11. 风险与保密问题

- 现有 Sites 前台无法直接访问仅存在于自托管内网的 FastAPI；公开部署前必须明确 API 域名、CORS、缓存和可用性策略。
- 本机当前没有 Docker，容器构建和真实 PostgreSQL 迁移需要在具备 Docker 的环境复验。
- 示例邮箱、域名和个人资料尚未由用户确认，继续使用明显占位值，不冒充真实信息。
- 发布内容必须经过保密检查，严禁真实设备数据、内部协议、客户信息、网络地址、密钥和未授权截图。
- 管理端不可复用 Sites 的浏览身份作为博客管理员会话，必须由 FastAPI 独立执行权限验证。
