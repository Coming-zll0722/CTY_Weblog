# 安全与保密检查清单

## 应用安全

- [ ] 管理员密码使用 Argon2id，设置最小长度并禁止常见密码。
- [ ] 会话 Cookie 启用 HttpOnly、Secure、SameSite；写请求启用 CSRF。
- [ ] 登录按账户和 IP 限流，失败响应不泄露账户是否存在。
- [ ] CORS 只允许明确域名，不与凭据模式同时使用通配符。
- [ ] Markdown 禁止危险 HTML，并对渲染结果执行白名单清洗。
- [ ] SQL 全部通过 SQLAlchemy 参数化执行。
- [ ] 上传校验扩展名、MIME、文件头、大小和图像尺寸。
- [ ] 管理接口执行服务端角色检查，不依赖隐藏按钮。
- [ ] 密钥、数据库密码和存储凭据只通过环境变量或密钥管理。
- [ ] 日志不记录密码、Token、Cookie、原始邮箱、正文和上传内容。
- [ ] Nginx 配置 CSP、HSTS、X-Content-Type-Options、Referrer-Policy。
- [ ] 每周执行依赖漏洞检查；高危漏洞在 72 小时内处理。
- [ ] 数据库每日备份，季度恢复演练。

## 发布内容保密审查

- [ ] 未出现公司或客户未公开名称。
- [ ] 未出现真实产品型号、设备编号或网络拓扑。
- [ ] 未复制内部源代码、协议原文、测试数据和日志。
- [ ] 未暴露 IP、端口、账号、令牌、文件路径和服务器信息。
- [ ] 未使用未经授权的系统或设备截图。
- [ ] 架构图已重新绘制，不能反推出内部组织和真实部署。
- [ ] 数据帧、地址、名称和时间已模拟或泛化。
- [ ] 项目结果避免披露合同、数量、性能和质量敏感指标。
- [ ] 图片元数据已移除。
- [ ] 发布者完成二次复核；不确定内容默认不发布。

## 已知风险与后续

- 首版示例内容为静态数据，尚未接入真实管理权限。
- 评论、公开上传和密码找回默认关闭，启用前必须补充反垃圾、审核和邮件安全。
- 内容安全策略在接入第三方评论、统计或字体后需重新评估。
